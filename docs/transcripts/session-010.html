Session 10: No imported text can become Scheme

Why. A whole-repository audit on 2026-11-02 (docs/planning/audit-2026-11-02.md; finding IDs below refer to it) found that a shared config or SVG can put executable Scheme into the exported .ly (H1). LilyPond runs it at compile time, and (system …) would run commands. The affected fields include labels and names that land in %% comments (where a newline ends the comment), lilypondVersion, schemeSymbols values, defaultMagnify, duration names, and path data taken verbatim from data-lilypond-* attributes, which the toolkit audit (M11) reached independently. Validation called these configs valid. 1.0.0 is tagged, and nothing is public; this ships as 1.0.1.

  1. Register.
  2. Route every value that cnb/src/cnb-lilypond.js emits through a small set of emitters, and never interpolate raw config text:
  • Comment text: control characters and newlines become spaces (this also covers L6).
  • Scheme strings: escape \ and ".
  • Symbols: match ^[a-z][a-z0-9-]*$, else the export fails with the field's name.
  • Numbers: finite JavaScript numbers, formatted by the exporter.
  • Versions: match ^\d+\.\d+\.\d+$.
  • Path data: parsed into commands and numbers and re-emitted from the numbers, including data-lilypond-* from imported SVGs. A path that does not parse is an import error, never text passed through.

Validation rejects every value the emitters would reject, so an invalid config never reaches export.

  1. M5: shape names whose slugs collide (Kite Up / kite-up), and names whose slug is empty (non-ASCII), get a validation error naming both shapes, or a deterministic disambiguating suffix. They never overwrite silently.
  2. Hostile-input tests:
  • Add the audit's payloads as fixtures: shared-config.json (newline plus #(display …) in the notation label), and an SVG whose data-lilypond-notehead carries #(display …), plus one payload per affected field.
  • Unit tests assert that each payload is either rejected, or exports a .ly in which no #( or $( appears outside the exporter's own constant template.
  • An engine-backed test, which skips with a reason when LilyPond is not on PATH, compiles each export and asserts that the payload text is never printed.

Run the cnb-unit suite.
