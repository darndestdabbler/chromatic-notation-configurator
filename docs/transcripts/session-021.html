Session 21: The colour picker stays open

Why. On 2026-11-05, while defining the 45deg-369 colours, the operator found that the colour picker closed on every change: a drag in the colour field or a typed digit in the RGB boxes shut it, so each hex digit had to be entered on its own, reopening the picker between digits. The cause is in the editors, not the browser: every colour <input> is wired to the input event, which fires on each drag step and each typed digit, and its handler calls changed(), which redraws the whole panel. The redraw destroys the element that owns the open picker, and the browser closes it. Four editors share the wiring: cnb/ui/palette-editor.js (custom palette cells), cnb/ui/notehead-rule-editor.js (a rule's explicit colour), cnb/ui/key-signature-editor.js (the separator colour) and cnb/ui/staff-rule-editor.js (staff and ledger line colour).

  1. Register.
  2. In each of the four editors, split the colour input's wiring: on input, update the state and call onChange so the preview follows the drag live, but do not redraw; on change, which fires when the picker closes, do the full changed() so derived text such as the palette's nearest-colour names catches up. Every other control keeps its wiring.
  3. Pin it in the test file named after each editor: an input event on a colour control leaves that same element in the DOM and emits onChange; a change event redraws. Run the four editors by hand in the browser (drag in the field, type a full hex value) and record the check in docs/uat-status.md.
