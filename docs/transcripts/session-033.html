Session 33: Stems engrave where the preview draws them

Why. Session 29's engine-backed stem test found that the exporter and the engine disagree on the units of a stem attachment. The exporter writes cnb:register-attachment! points in staff spaces (LY spec §4.4, §4.4a), but the engine passes them unchanged to LilyPond's NoteHead.stem-attachment (cnb/stems.ly), which reads each as a fraction of the notehead's half-width and half-height, −1 to 1 (the engine's own default, '(1 . 0), is the right edge). So every exported shape with stems engraves them nearer the centre than the preview draws them: the default crotchet's up stem sits 0.105 staff spaces right of the note's centre on the page and 0.393 in the preview, its repeat-mode minim 0.176 against 0.558. The Kite fixture is right only because its lilypondAnchors were hand-set to the golden file's relative numbers. Every 1.0.0 export with stems is affected, so this goes before the release.

  1. Register.
  2. The exporter (cnb/src/cnb-lilypond.js) writes each attachment in LilyPond's relative units: x ÷ half the registered path's width, y ÷ half its height, measured from the path it registers, so a sized variant (§4.1c) keeps the same relative point. The pitch-axis substitution (§4.4a) no longer enters, since the unit cancels. lilypondAnchors stay semitone units in the config.
  3. The Kite fixture's lilypondAnchors become true semitone anchors that export to the golden file's (0 . 0.9) / (-0.365 . 0.9); check the 45deg-369 fixture and the gallery files the same way. Regenerate the default, Kite 4-369, 45deg-369, sized and Twinline baselines, and record the change as LY spec 1.3.7, with a note that 1.0.0 exports with stems should be regenerated.
  4. Remove the skip from session 29's test in cnb/tests/cnb-card-tests.js ("repeat mode (engine): the engraved stem x matches the preview's"): minims and crotchets, stem up and down, within half the engraved stem width, since LilyPond puts the stem's edge, not its centre, at the attachment point. If that half width proves visible, decide with the operator whether the preview or the export moves.
