## HIGH

### H1. Scheme code injection: strings from a shared config JSON or SVG reach the `.ly` unescaped
- **Where:** `cnb/src/cnb-lilypond.js`
  - :496 `\version "${engine.lilypondVersion}"`
  - :501 `%% ${meta.notationLabel}`
  - :507 `%% Source: ${meta.configName}.json`
  - :510 and :605 `palette.name` in `%%` comments
  - :545 and :550 `shape.lilypondPath` / `lilypondHollowPath` emitted verbatim inside `#(define …)`
  - :616, :622, :815 `palette.schemeSymbols` values emitted as raw symbols
  - :691 `engine.defaultMagnify` emitted raw
  - :838 and :861 duration names inside `;;` comments

  The data comes in through `cnb/ui/svg-importer.js:295-296,430-431`, which copies `data-lilypond-notehead` / `data-lilypond-hollow` verbatim. `cnb/ui/config-io.js` (`checkKinds` checks only the JSON kind) and `CNBConfig.validate` (`cnb/src/cnb-config.js:300-807`) check none of these fields.
- **Defect:** Only the three B3 metadata strings go through `escSchemeString`. Every other string field from an imported config or SVG goes into the export with no escaping or validation. A newline in a `%%` or `;;` comment field ends the comment; a raw path or symbol field is Scheme source.
- **Failure scenario:** A user opens a shared `.cnb.json` whose `meta.notationLabel` is `"Innocent\n#(display \"INJECTED\")\n%%"`, exports, and engraves. LilyPond runs the injected Scheme, and `(system "...")` would work the same way. A shared toolkit SVG whose `data-lilypond-notehead` is `'()) (system "...") (define x '()` does the same with no visible sign in the preview. Validation reports the config as valid in both cases.
- **Verified:**
  - `poc1.mjs`: every listed field reaches the output as live code after `CNBConfigIO.loadFromText` → `CNBLilypond.generate` (validation `valid: true`).
  - `poc2.mjs` + `audit-ly/score.ly`: real LilyPond 2.24.2 printed `INJECTED-VIA-NOTATION-LABEL` and reported "Success: compilation successfully completed".
  - The HTML side is clean: no `innerHTML`/`insertAdjacentHTML`/`eval`; all imported text goes through `textContent`, `setAttribute`, or CSSOM properties.
- **Fix:**
  - Never emit raw strings. Strip or replace CR/LF (and other control characters) in comment text.
  - Accept `lilypondPath` only if it parses as a strict `'((moveto|lineto|curveto|closepath) <numbers>…)` list, and re-serialize it from the parsed numbers.
  - Run symbols through `slug()`; require `defaultMagnify` to match `^\d+(\.\d+)?(/\d+)?$` and `lilypondVersion` to match `^\d+\.\d+(\.\d+)?$`.
  - Add a validate() error for each, plus a unit test per field.

### H2. Toolkit pre-baked paths are in semitone units, but the exporter emits them as staff-space units (wrong size whenever sps ≠ 1)
- **Where:** `cnb/src/cnb-lilypond.js:545,550` (verbatim emit) vs `:216-249` (anchors *are* divided by sps); `cnb/ui/svg-importer.js:27,430-431`. Toolkit side: `music_glyph_toolkit.py:572` `format_scheme(scale=0.01)` and README "LilyPond Path Data Attributes" (÷100 of 100-units-per-semitone gives semitones).
- **Defect:** The engine draws registered paths in staff-space units with no sps division (`cnb/stencils.ly:99-115,202`). The configurator divides anchors by `semitonesPerStaffSpace` at export but passes `lilypondPath` through untouched. Real toolkit output is therefore drawn sps× too large, and its stems attach at points that no longer match the head.
- **Failure scenario:** Kite at sps 3. The toolkit writes `(moveto 0 2) (lineto 2 1) …` for `kite-up.svg`. Exported and engraved, the noteheads are 3× too big (`audit-ly/score-toolkit.cropped.png` vs `score-fixture.cropped.png`).
- **Why the tests pass:** Every checked-in pre-baked path is hand-pre-divided by sps.
  - `cnb/fixtures/kite-up.svg`, `kite-down.svg`, `kite-4-369-config.json`: 0.6667 = 200/(100×3). The SVG's comment calls this "music-glyph-toolkit output format", but the toolkit would write 2.0.
  - The twinline gallery shape: about 1.0 tall for 2 semitones at sps 2.
  - So the release-gate "pixel-identical" round trip (`uat-kite-pipeline.mjs`, README "A worked example") cannot catch it.
- **Verified:** Read the toolkit source; `kite-toolkit.mjs` builds the config with toolkit-format paths; rendered both versions through the engine.
- **Fix:** At export, scale pre-baked path coordinates by 1/sps (1/`axisUnitsPerStaffSpace` under an axis), exactly as anchors are, by parsing and re-serializing (which also closes H1 for paths). Regenerate the fixtures from real toolkit output.

### H3. Fallback `svgPathToLilypond` emits raw SVG coordinates (no ÷units-per-semitone, no ÷sps, no Y flip): the default config and 17 of 18 gallery examples export huge, mirrored noteheads
- **Where:** `cnb/src/cnb-lilypond.js:365-421` ("No scaling or Y-inversion is applied"), used at :545/:550 whenever `lilypondPath` is null.
- **Defect:** The shapes that reach the fallback store `svgPath` in native SVG units: the default `crotchet-minim` has naturalHeight 272.4 and spans ±163; the gallery shapes are 136–150 units/semitone. Those coordinates are written to the `.ly` verbatim.
- **Failure scenario:** Exporting the out-of-the-box default config (or any gallery example except twinline-compact) and engraving four quarter notes produces one notehead that fills the page. LilyPond warns "compressing over-full page by 116.4 staff-spaces" (`audit-ly/default-score.png`). The same happens for any SVG imported without `data-lilypond-*`, which the README describes as "fall back to automatic path conversion at export".
- **Verified:**
  - Rendered `default-config.ly` through the engine.
  - Every gallery shape except twinline's has `lilypondPath: null` (surveyed all 18 files).
  - `cnb/fixtures/default-export-baseline.ly:24-41` pins the 163.578-unit output, and `check-gallery-examples.js` asserts only that `generate()` doesn't throw. Both gates pass on unusable output.
- **Fix:** In the fallback, divide by `naturalHeight/semitoneHeight` and then by sps (or axis units), and negate Y, matching `attachmentPoints()`'s fallback. Regenerate the baselines, and add one engine render (or at least a bbox-height assertion) to the gates.

### H4. Duration categories are off by one between the exporter and the engine: a "minims are hollow" rule hollows quarter notes
- **Where:**
  - Configurator: `cnb/src/cnb-config.js:121-124` (crotchet 3, minim 2, semibreve 1, breve 0), emitted as `(= duration N)` at `cnb/src/cnb-lilypond.js:848-862`.
  - Engine: `cnb/utils.ly:331-336` `cnb:duration-category` computes breve/whole → 0, half → 1, quarter → 2, eighth+ → 3. `procedure.ly:476-501` keys the config cache by that value.
  - The engine's own `procedure.ly` doc and the export spec both say 3 = quarter, so the engine disagrees with its own spec.
- **Defect:** Every duration-aware Section C clause lands on the wrong note values: crotchet clauses match only eighths and shorter, minim clauses match quarters, semibreve clauses match halves.
- **Failure scenario:** Kite fixture plus rules "C solid" and "C minims hollow" (priority 51, `durations: ["minim"]`). Engraving `c'8 c'4 c'2 c'1` shows the quarter hollow and the half solid (`audit-ly/score-dur.cropped.png`).
- **Verified:** In LilyPond, `(cnb:duration-category (ly:make-duration 2))` → 2 (`audit-ly/durcat.ly`); full render as above.
- **Fix:** Agree on one mapping across the two repos. Either fix the engine's `cnb:duration-category` to match the spec (quarter = 3), or change the configurator's `lilypondDuration` values and the spec. Add an engine-backed test with a duration-varying rule.

## MEDIUM

### M1. Setting a stem thickness breaks compilation: `cnb:stem-thickness` does not exist in the engine
- **Where:** `cnb/src/cnb-lilypond.js:718-720`; the UI control is at `cnb/ui/common-props-editor.js:~495-506`. Spec v1.2 tables list `cnb:stem-thickness`.
- **Defect:** The engine never defines `cnb:stem-thickness`, so the emitted `#(set! cnb:stem-thickness …)` is a Guile "Unbound variable" error.
- **Failure scenario:** The user unticks "auto" stem thickness, enters 1.5, and exports. LilyPond reports `Unbound variable: cnb:stem-thickness` and `fatal error: failed files` (exit 1).
- **Verified:** `audit-ly/kite-stem.ly` + `log-stem.txt`; grepped every engine `.ly` for a definition.
- **Fix:** Add the variable (and its use) to the engine, or remove the control and the emission until it exists.

### M2. Staff-line color and thickness are exported but the engine ignores them
- **Where:** `cnb/src/cnb-lilypond.js:707-716`; engine `cnb/staff.ly:254-290`. `cnb:default-staff-line-thickness` and `cnb:default-staff-line-color` are read only in "advanced mode" (non-empty `cnb:staff-and-ledger-lines`), which the configurator never emits.
- **Defect:** The UI controls change the preview and the `.ly` text but not the engraving. Separately, the thickness value is written in staff-space units (`pct/100/sps`, e.g. 0.2667), while the engine reads it as a markup `thickness` (line-thickness multiples, default 2).
- **Related:** Ledger templates, proximity, and ledger styling are never exported either. The engine auto-generates ledgers from staff spacing (`ledgers.ly:82-165`), so the configured ledger rules are preview-only, and no document says so.
- **Failure scenario:** Staff color `#FF0000` at 80% thickness: the render shows normal black lines (`audit-ly/score-staffstyle.cropped.png`).
- **Verified:** Rendered through the engine.
- **Fix:** Emit `cnb:staff-and-ledger-lines` (advanced mode) with correctly-unitized thickness, and ledger overrides/positions. Otherwise mark these controls preview-only in the UI and docs and stop emitting no-op settings.

### M3. Key-scoped notehead rules show in the preview but vanish from the export with no warning
- **Where:** `cnb/src/cnb-lilypond.js:114,784` (always resolves with `key = null`); `cnb/src/cnb-card.js:113-135` (the preview passes the real key). The README advertises rules "by pitch/duration/key".
- **Defect:** A rule with `match.keys: ["G major"]` never matches during export. `validate()` gives no warning, and `config-export.js` documents the limitation only in a code comment.
- **Failure scenario:** "F♯ red in G major": the preview shows it red, the export has no `#FF0000` anywhere, and validation is clean.
- **Verified:** `keyrule.mjs`.
- **Fix:** Add a validate() warning (and a note in the rule editor) whenever a rule's `match.keys` is not `"all"`. Better, emit key conditions (the engine passes `key` as a pitch-class list).

### M4. Any staff-editor edit forces `staff.midpoint` to 12 and `semitonesPerStaffSpace` to the GCD, silently moving pitch-axis configs
- **Where:** `cnb/ui/staff-rule-editor.js:160-162` (midpoint hard-coded 12), `:194-206` (`buildStaff`), `:351-356` (every change emits the rebuilt slice).
- **Defect:** A loaded config whose midpoint isn't 12 is rewritten the first time any staff field is touched, even a cosmetic one. Under a pitch axis the midpoint anchors the axis, so the whole export shifts.
- **Failure scenario:** Load gallery `twinline-compact.json` (midpoint 7) and change the staff line color. The export changes:
  - `staff-line-positions` goes from `'(-3 -1 1 4 6 8)` to `'(-6 -4 -2 1 3 5)`
  - the hook anchor goes from 4 to 7
  - `cnb:keysig-tonic-octave` goes from 0 to 1
- **Verified:** `twin.mjs` (calls the editor's own `stateFromConfig`/`buildStaff`); `staffedit.mjs` checked all 18 gallery configs, and twinline is the one affected.
- **Fix:** Keep midpoint (and sps when a pitch axis is enabled) from the loaded config in editor state instead of re-deriving them, or make them explicit editable fields.

### M5. Shape names that slug alike, or slug to nothing, produce wrong or invalid Scheme with no validation error
- **Where:** `cnb/src/cnb-lilypond.js:68-74` (`slug`), :540-560, :277. Names come from SVG filenames: `cnb/ui/svg-importer.js:83-87`.
- **Defect:** Section A/C identifiers are `slug(name)`, with no uniqueness check and no non-empty check.
- **Failure scenarios:**
  - Importing `Kite Up.svg` and `kite-up.svg` gives both the identifier `kite-up`: two `cnb:kite-up-path` defines, and the last one wins for every pitch class.
  - Importing `音符.svg` emits `#(define cnb:-path …)` and `#(cnb:register-path! ' cnb:-path)`, which is a broken registration.

  Validation passes in both cases.
- **Verified:** `slug.mjs`.
- **Fix:** In validate(), error on an empty slug or on two shapes with the same slug (and do the same for clef names). Or derive unique identifiers, e.g. by appending an index.

### M6. README and source comments point to a git tag that doesn't exist on the public remote
- **Where:**
  - `README.md` "Current Status": "preserved at git tag `legacy-monolith-final`"
  - `cnb/src/cnb-lilypond.js:8`
  - `docs/planning/project-plan.md:44`

- **Verified:** `git tag` vs `git ls-remote`.

## LOW

### L1. The staff editor's "derived LilyPond geometry" panel is wrong under a pitch axis
- **Where:** `cnb/ui/staff-rule-editor.js:26-31,406-424`. README §3 says the panel "shows the exact LilyPond geometry the export will emit".
- **Defect:** `derivedGeometry()` always uses the linear formula, while the exporter uses the axis formula.
- **Failure scenario:** For twinline-compact the panel shows `(-20 -14 -12 -8 -6 4 10 12 16 18)`; the export emits `'(-3 -1 1 4 6 8)`.
- **Verified:** `staffedit.mjs`.
- **Fix:** Have the panel call `CNBLilypond.computeStaffLinePositions` on the current full config.

### L2. `palette.useCBSafe` doesn't affect the export, though the code and header say it does
- **Where:** `cnb/ui/palette-editor.js:24` ("render/export toggle"); `cnb/src/cnb-lilypond.js:256,510`.
- **Defect:** With CB-safe on, the export header reads "Color palette: X (cb-safe)", yet the file renders the primary palette unless the score sets `cnb:use-accessible-colors`. What the preview shows and what is engraved differ.
- **Failure scenario:** A user who tunes the design in CB-safe mode exports a file that renders different colors than they designed against.
- **Verified:** Read the export: nothing reads `useCBSafe` except the header label.
- **Fix:** Emit `#(define cnb:use-accessible-colors #t)` (guarded by `defined?`) when `useCBSafe` is on, or relabel the header and the toggle as preview-only.

### L3. Preview repeat counts don't match the engine
- **Where:** `cnb/src/cnb-config.js:127` (minim 2, semibreve 4, breve 8, editable) vs engine `stencils.ly:158-169` (half ×2, whole ×4, breve ×4, fixed). `repeatCounts` is never exported.
- **Defect:** In "repeat" mode the preview draws breves ×8 and honors user-edited counts; the engine ignores both.
- **Failure scenario:** A user sets minim ×3: the preview shows three heads, the engraving two.
- **Verified:** Read the engine code; the render in H4 shows half ×2 and whole ×4.
- **Fix:** Document repeatCounts as preview-only and default breve to 4, or export the counts once the engine supports them.

### L4. Every test `approx()` helper passes on NaN
- **Where:** e.g. `cnb/tests/cnb-card-tests.js:24-26`. All 11 copies use `if (Math.abs(a - b) > tol) throw`.
- **Defect:** `approx(undefined, 3.2)` passes silently, so a misspelled property or a NaN regression in any geometry test cannot fail.
- **Failure scenario:** A future rename of a grid or card field leaves its geometry tests green.
- **Verified:** Rewrote every helper as `!(… <= tol)` in the worktree; still 831/831, so no test hides a NaN today. The weakness is latent.
- **Fix:** Use `if (!(Math.abs(a - b) <= tol))` (or check `Number.isFinite(a)`).

### L5. The test runner silently skips a file with no `tests` export
- **Where:** `cnb/tests/run-tests.js:72-75`.
- **Defect:** The skip prints a message but doesn't count a failure, so renaming or breaking the export of a test file drops it from the run while the suite still reports "All tests passed".
- **Failure scenario:** A test file whose `tests` export is renamed during a refactor quietly stops running.
- **Verified:** Read the runner. All 26 files on disk are currently listed and load.
- **Fix:** Count a missing `tests` array as a failure. Also consider globbing `*-tests.js` instead of the hand-maintained list, which `dabbler.yaml` already describes as "every cnb/tests/*-tests.js".

### L6. Header `\version` and comments have no length or charset guard (cosmetic side of H1)
- **Where:** `cnb/src/cnb-lilypond.js:496-510`.
- **Defect:** Even without hostile intent, a config name or label with a newline (possible from foreign JSON) breaks the `.ly` syntax.
- **Failure scenario:** `notationLabel: "Line1\nLine2"` makes the export a LilyPond syntax error.
- **Verified:** Same mechanism as H1 (the first `poc2` run showed a syntax error at the comment break).
- **Fix:** Covered by the H1 fix (strip CR/LF in comments).

### L7. README project tree claims "cnb/assets/ Built-in shapes and palettes"
- **Where:** `README.md:352`.
- **Defect:** `cnb/assets/` contains only `examples/gallery/*.json`. Shapes and palettes live in code (`cnb-config.js`, `palette-editor.js`).
- **Failure scenario:** A reader looks in `assets/` for shapes and palettes that aren't there.
- **Verified:** `ls cnb/assets`.
- **Fix:** Say "Gallery example configs".

## Checked and clean (not findings)
- **HTML injection:** none. All imported strings are rendered with `textContent`, `setAttribute`, or CSSOM style properties. No `innerHTML`, `insertAdjacentHTML`, or `eval`.

Both sides ignore `transform` attributes the same way. The only contract break is path units (H2).
- **Engine variables:** every other `set!` target the exporter emits exists in the engine (`config.ly`).
- **Markdown links:** no broken relative links in the non-historical docs (README, CLAUDE.md, docs/playbook, docs/planning, docs/research, docs/*.md). `legacy/` mentions remain only in historical session and plan text.
